# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| environment-recorded | The repro report's environment/setup section, checked against the repo-facts block's version info | Pass: the report states concrete environment details (OS/runtime version, dependency versions, any required config or flags) precise enough for a stranger to recreate the same setup. Fail: vague statements like "set up the project locally" with no specifics, or no environment mentioned at all. | required |
| steps-rerunnable | The reproduction steps listed in the repro report | Pass: the steps, together with any commands shown and any inputs shown or precisely described (exact parameter values, file contents, or a specific quoted script), give enough detail that following them would trigger the same behavior — even when an input isn't pasted verbatim, as long as its defining characteristics are stated precisely enough to reconstruct something producing the same result. Referencing input already shown in the issue thread is fine, as long as the specific values/parameters used are named exactly. Fail: a step names an action with no way to know what to actually run or type ("set up the project", "run the tests" with no command), a necessary step is omitted, or an input is described so loosely that two different people following it could plausibly get different behavior. | required |
| outcome-stated-honestly | The repro report's stated conclusion (reproduced / could not reproduce), checked against the evidence actually shown | Pass: the conclusion matches the evidence — an honest "could not reproduce" backed by what was actually tried also counts as a pass. Fail: claims success with no supporting evidence, or the shown output contradicts the stated conclusion. | required |
| conventions-respected | The repo's CONTRIBUTING.md / AI-assistance policy files, checked against the claim and repro comment text | Pass: the comments comply with the repo's stated policy — in particular, if the repo requires disclosing AI assistance, the comment discloses it. Fail: the repo has a disclosure requirement and the comment doesn't disclose, or the comment otherwise clearly violates a stated contribution rule. | required |
| claim-promises-not-asserts | The claim comment text | Pass: the claim may state that the issue has been reproduced, when that statement is backed by evidence in the package (a repro report or described observation) — this is a factual report, not overclaiming. Any investigation or next steps must be framed in future/intent language ("I'll trace...", "my next step is...") with no promised fix date or guaranteed outcome. Fail: the claim asserts a root cause, diagnosis, or fix as already established/certain; claims the bug has already been reproduced with no evidence to back it (in a claim-only draft); or promises a specific delivery timeline or guarantees a fix/result ("I will fix this within 2 days guaranteed", "PR by Friday"). | required |

## Verdict rule

accept if every required check passes; preferred checks never change the verdict; unclear counts as fail.
